GXP GATEWAY AUDIT

Your AI, APIs and gateways touch lab systems.
Who keeps the audit trail?

GxP Gateway Audit (package mcp-glp-audit-proxy) is a self-hosted reverse proxy between your clients and the systems they call. It audits MCP and HTTPS channels: MCP tools, APIs, gateways and LLM calls. Every call goes into a tamper-evident, fail-closed hash-chained audit trail, as a complement to your systems' own audit trail. Designed to support GLP/GxP, 21 CFR Part 11 and EU GMP Annex 11 workflows.

How it works

Clients → GxP Gateway Audit (MCP / HTTPS, always TLS) → MCP servers, APIs, gateways, LLM endpoints


1. Connect

It runs as a reverse proxy: the client only changes its base URL. Supported flows: mcp2mcp, mcp2api, api2mcp, api2api, mcp2llm, api2llm. Always TLS; authentication by mTLS and/or token.

2. Record

Every call is appended to a hash-chained audit trail (audit schema 1.3.0). You choose how bodies are stored: hash only (default), redacted or full.

3. Fail closed & verify

If a record is deleted or the chain is broken, it stops and alerts, saying which record and when. Archive manifests and a review command help you check the trail; offline runs keep their own hash-chained run log.

Offline regulatory report

  • An offline command lists regulations by type and country.
  • For each one it says whether your current configuration supports it, and names the parameter to change if it does not.
  • It runs offline and writes its own hash-chained run log.

These materials support your own validation process; your organisation remains responsible for validating its use.
